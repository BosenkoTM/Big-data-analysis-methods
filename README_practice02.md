### 2.3. Служебный код или ошибка ввода?

Пропуск в выгрузке часто не пустая ячейка, а **служебное значение**. Поэтому `isna().sum() = 0` ещё не означает, что пропусков нет.

- **Служебный код:** одно и то же невозможное значение, которое повторяется очень часто. Это договорённость системы:
  «нет данных» → пропуск, флаг `missing_code`.
- **Ошибка ввода:** разные значения чуть выше шкалы, по несколько раз каждое. Значение ошибочно → пропуск, флаг `out_of_range`.

В обоих случаях строка **остаётся** в данных, исходное значение сохраняется в `score_raw`.

### 2.4. Показатели качества

| Показатель | Как считаем |
|---|---|
| **C** — полнота | доля строк, где `score` известен (не пусто и не служебный код) |
| **V** — валидность | доля значений в шкале 0–100 **среди заполненных** |
| **U** — уникальность | число уникальных ключей `(id_assessment, id_student)` / число строк |
| **S** — согласованность | доля строк, где тип задания записан по словарю `{TMA, CMA, Exam}` и нет противоречия «Withdrawn + Exam» |

$$DQ = 0{,}35C + 0{,}30V + 0{,}20U + 0{,}15S$$

Веса — учебная договорённость, а не стандарт. Высокое DQ может скрывать серьёзную проблему в одном измерении.

### 2.5. Порядок конвейера очистки

```text
0. raw-срез варианта
1. удалить точные дубли          (строка повторяется целиком)
2. привести типы                 (текст → числа; '?' в сроке → NaN)
3. удалить логические дубли      (тот же ключ, другой event_id; оставить первую доставку)
4. коды пропуска и диапазон score (значение → NaN + флаг; строку НЕ удалять)
5. нормализовать категории       (tma, Tma → TMA)
6. признаки и флаги              (days_late, withdrawn_exam)
```

Порядок важен: если посчитать средний балл до шага 4, служебные коды исказят результат; если не удалить дубли, часть студентов получит лишний вес.

### 2.6. pandas ↔ GoogleSQL

| pandas | GoogleSQL |
|---|---|
| `pd.to_numeric(x, errors="coerce")` | `SAFE_CAST(x AS INT64)` |
| `df.drop_duplicates()` | `SELECT DISTINCT *` |
| `sort_values(...).drop_duplicates(subset=KEY, keep="first")` | `QUALIFY ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...) = 1` |
| `x.isin([...])` | `x IN (...)` |
| `(cond).sum()` | `COUNTIF(cond)` |
| `str.strip().str.upper()` | `UPPER(TRIM(x))` |
| `quantile(0.25)` | `PERCENTILE_CONT(x, 0.25) OVER ()` |

### 6.3. Загрузка `practice02_raw.csv`: все 12 полей — STRING

Raw-слой хранит выгрузку «как есть», поэтому **все поля должны быть `STRING`** — это контракт данных из лекции 2:

**Способ 2 — вручную в консоли BigQuery** (для знакомства с интерфейсом):

1. Выполните ячейку 9.4а: она напечатает схему **одной строкой**.
2. Датасет вашей группы → ⋮ → **Create table**.
3. **Source:** `Create table from` = **Upload**, файл `practice02_raw.csv`, `File format` = **CSV**.

### 7.1. Clean-слой — серия из четырёх представлений

Каждое представление — один шаг конвейера поверх предыдущего (тот же порядок, что в pandas, раздел 2.5).
Представления создаются **один раз на всю таблицу**; фильтр варианта применяется при запросах к ним.

```text
p02_raw ──► p02_s1_distinct ──► p02_s2_typed ──► p02_s3_dedup ──► p02_clean
            SELECT DISTINCT *    SAFE_CAST,       QUALIFY           UPPER(TRIM(...)),
            (точные дубли)       коды → NULL      ROW_NUMBER() = 1  флаги, days_late
                                                  (логич. дубли)
```

| Представление | Запрос | Шаг конвейера | Что делает |
|---|---|---|---|
| `p02_s1_distinct` | 7.1 `q4a_s1_distinct` | 1 | убирает точные дубли |
| `p02_s2_typed` | 7.2 `q4b_s2_typed` | 2 | приводит типы через `SAFE_CAST`, служебные коды балла → `NULL` |
| `p02_s3_dedup` | 7.3 `q4c_s3_dedup` | 3 | оставляет первую доставку для пары «задание — студент» |

# 9. BigQuery Sandbox: что важно помнить

- до **10 GiB** хранилища и **1 TiB** обрабатываемых запросами данных в месяц бесплатно;

  один раз в `DATASET` (ячейка 9.1); датасет и представления должны быть в одной локации (`EU`).

# 11. Типичные ошибки

| Ситуация | Что проверить |
|---|---|
| Средний балл больше 80, а в `score` есть числа 999 | не прочитан ли файл без `dtype=str`; заданы ли `MISSING_CODES` |
| «значение … похоже на служебный код» | добавьте часто повторяющееся невозможное значение в `MISSING_CODES` |
| «это ошибка ввода, а не код» | значения 101–120 — ошибки ввода, их не нужно включать в `MISSING_CODES` |
| «assessment_type содержит значения вне словаря» | в `TYPE_MAP` нет ключа после `.strip().upper()`, например `EXAM` |
| *Empty schema specified* при ручной загрузке | поле **Edit as text** пустое: щёлкните внутрь редактора и вставьте строку из 9.4а; переключатели после вставки не трогайте. Проще — загрузка из Colab (9.4б) |
| Загрузка в BigQuery упала на `'?'` | включён Auto detect; используйте явную схему (все поля `STRING`) или загрузку из Colab |
| Запрос 1: `header_as_data = 1`, строк 176 173 | при ручной загрузке не указан `Header rows to skip = 1`; перезагрузите таблицу (9.4б перезаписывает её) |
| В редакторе BigQuery `Syntax error` на строке `PROJECT_ID = …` или `SQL = {` | в BigQuery вставлен код Python. Python — в Colab; в консоль копируйте только напечатанный SQL |
| `Not found: Dataset …` | в `DATASET` указано не то имя (у групп разные датасеты) или датасет в другом проекте; сверьте с Explorer |
| `PROJECT_ID: строчные латинские буквы…` или `Not found: Project` | указано отображаемое имя проекта вместо Project ID |
| `В запросе … остался пропуск ___` | не заполнен TODO-4, TODO-5 или TODO-6 |
| TODO-5: журналы не совпали | в `PARTITION BY` не весь ключ `(id_assessment, id_student)` или в `ORDER BY` не `event_id` |
| `No matching signature for function CONCAT` | в clean-слое ключи — `INT64`; используйте `CAST(... AS STRING)`, как в `q5` |
| `q5` дал другое число строк, чем pandas | таблица загружена не полностью (запрос 1); в 7.4 добавлен лишний фильтр |
| Сверка не прошла | чужой вариант на шаге 0; ячейки Colab не перезапущены после правки правил; при пути CSV — файл не от `q8_check` |
| Почти все CMA «опоздали» | это не ошибка расчёта: поле срока для CMA не означает жёсткий дедлайн — опишите это как ограничение |
